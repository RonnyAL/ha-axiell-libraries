# Axiell Libraries 0.6.0

Restore saved loan information after a Home Assistant reload or restart. Each
account now has a private, atomic Store snapshot of normalized loan/catalogue
display fields and its historical fetch time. A valid account-bound snapshot
restores all loan entities coherently as **stale**, then a background read tries
to replace it. Successfully fetched empty lists are saved too; a failed read
never invents zero loans. Snapshots have no automatic age cutoff: check their
timestamp before relying on due dates.

Add a diagnostic **Last successful refresh** timestamp sensor and a native
**Refresh now** button. The button reuses the account's coordinator, session and
persistent DeviceID, subject to native debouncing and provider cooldowns. Its
last-pressed time records a request, which can be queued or fail. Check the
timestamp and **Data freshness** for the read result. The historical timestamp
can remain visible when loan content is withheld; the button never renews loans.

Existing accounts, DeviceIDs, entity IDs, polling options, bounded recovery and
read-only to-do lists remain compatible. Credential/security failures withhold
loan content from entity attributes and to-do responses until a successful read.
Restored loans and old consent cannot authorize renewal: explicit individual
renewal still requires permission, fresh preflight and current manual consent.
Renewal writes are never automatically repeated.

Back up Home Assistant and restart after updating. Requires Home Assistant
2026.11.0 or later; target 2026.11.1 and Python 3.14. The first upgrade has no
snapshot until a successful loan read; Recorder history cannot supply one. With
no valid cache, setup still needs a successful first read and follows native
setup retry/reauthentication. Reload/teardown can briefly remove entities even
when restoration is available.

Snapshots live under HA's `.storage`, with private file permissions and atomic
writes, **not encryption**. They exclude raw authentication/API data and renewal
state, but contain reading history; protect HA configuration and backups.
Recorder's rich-attribute exclusions do not exclude these separate snapshots
from backups. Unload retains the snapshot; removing an entry requests its
deletion, and an account identity change discards the previous cache.

Storage failures do not fail an otherwise successful loan read and can leave an
older snapshot on disk. Saves are skipped while HA is stopping to prevent
deferred writes from recreating removed data, so a late read can also leave
older history. Unsafe failures attempt durable withholding or cache removal.
If all marker writes and removals fail, an in-process block protects reloads,
but withholding cannot be guaranteed after process loss. Check freshness and
age after restoration; cache persistence depends on working storage.
