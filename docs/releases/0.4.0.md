# Axiell Libraries 0.4.0

Version 0.4.0 adds explicit individual loan renewal with informed consent.

Administrators can run `axiell_libraries.renew_loan` in Developer tools → Actions
for one selected library/card entry and `loan_id`. The coordinator refreshes
current loans before writing, and preserves per-account authentication and the
persistent DeviceID. The read-only to-do list and existing sensors retain their
identities; there are no bulk or automatic renewals.

Known positive renewal costs and each provider prompt require manual consent.
Review the message, then call again with `confirm: true` and its local
`confirmation_id`. IDs expire after ten minutes, are single-use, belong to the
specific account/copy/circulation state, and disappear on reload or restart.
Raw provider acknowledgement codes are never accepted from action callers.
See the [complete action guide](https://github.com/RonnyAL/ha-axiell-libraries/blob/v0.4.0/docs/home-assistant-ui.md#renew-one-loan).

Response callers receive renewal/confirmation status and sanitized messages.
Ordinary callers receive translated errors when confirmation or intervention
is needed. A successful write with failed refresh is explicitly distinguished
from an unknown outcome: use Update entity for the former; check the library's
account before retrying the latter. Writes are never automatically repeated.
Polling and writes are serialized; unloading drains active writes safely.

Provider text is bounded, stripped of HTML/control content and redacted for
known secrets. Arbitrary personal provider prose may remain; treat it as
private. The existing wrapper uses AppID as TemplateID, as in verified
login; distinct-template providers remain an unverified limitation.

Offline synthetic tests cover transport, confirmation, isolation, concurrency,
HA registration/authorization, responses/errors and packaging. No live renewal
or provider challenge chain has been performed. Existing owner-verified login,
aggregate sensors and Marketplace installation do not verify renewal. See the
[validation ledger](https://github.com/RonnyAL/ha-axiell-libraries/blob/v0.4.0/docs/validation.md) for exact runtime evidence and final gates.

Before upgrading, back up HA; after installing, restart HA. Config entries,
PIN storage, persistent DeviceIDs and entity IDs need no migration. The canonical
Git tag is `v0.4.0`; the manifest version and release title are `0.4.0`. See
[release recovery](https://github.com/RonnyAL/ha-axiell-libraries/blob/v0.4.0/docs/releases.md#publication-workflow)
for the manual workflow and partial-publication recovery procedure.
