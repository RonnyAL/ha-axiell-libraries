# Home Assistant 2026.11 and Marketplace implementation plan

> Use Superpowers subagent-driven development, TDD, task review, and verification
> before completion. Existing approved integration design remains unchanged.

**Spec:** `docs/superpowers/specs/2026-11-13-ha-2026-11-marketplace-design.md`

**Goal:** Verified Core 2026.11 compatibility, direct Marketplace packaging,
automated validation and a reviewable GitHub pull request.

## Global Constraints

- One entry per library/card; reject duplicate accounts before login.
- Generate `secrets.token_hex(8)` once per flow and persist DeviceID in entry data;
  retain it through retries, refresh, restart, reauthentication and upgrades.
- Keep async HA-managed aiohttp, trusted HTTPS Solus endpoints, bounded retries,
  `LoginPreSession` → `LoginCheckSession` → `LoansGet` → `RecordGet`, dueObject
  dates, direct RecordGet covers, manual LocationID and read-only behavior.
- All API tests offline with synthetic data; no APKs, credentials, tokens or raw
  personal responses. Do not change repository visibility, merge or publish.
- Actual Core 2026.11.1 and 2026.11.0 must run the complete tests; no compatibility
  claim from dependency pins alone. Report real failures and verified outputs.
- Commit green changes in small commits. Review every task.
