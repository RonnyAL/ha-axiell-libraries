# Release 0.5.0

The owner explicitly requested `release` after reviewing the reliability change.
Publish that work as 0.5.0 without changing repository visibility or deploying
anything to Home Assistant. Future releases and live renewals remain separate.

1. Prepare manifest 0.5.0, changelog/release notes and Marketplace upgrade tests.
2. Preserve the existing manual release workflow. The available GitHub connector
   cannot dispatch it and the local CLI cannot reach GitHub, so add one publication
   workflow fixed to 0.5.0, main pushes touching that file, and the explicit
   `[publish-v0.5.0]` commit marker. Require the full reusable validation, exact
   validated SHA and atomic creation of a previously absent tag.
3. Independently review the publication gates and run offline shell tests with
   a recording fake gh. No writes in tests.
4. Push a release-preparation branch and PR through the connected GitHub API.
   Run the supported 2026.11.0/2026.11.1 tests, pinned Ruff and hassfest in CI.
5. Fix any failures, then merge the verified PR with the explicit release marker.
   Await the publication workflow's repeated full validation and publication.
6. Verify v0.5.0 tag, published release, manifest and validated commit agree.
   Never move or delete an existing tag, or blindly rerun a partial publication.

Local verification remains supplemental until the supported CI matrix succeeds.
